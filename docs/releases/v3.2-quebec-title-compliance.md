# v3.2 — Quebec title compliance — April 2026

This release brings the application into compliance with the Quebec reserved-title regime (the title "Engineer" / "Ingénieur" is protected by law and reserved for members in good standing of the [Ordre des ingénieurs du Québec, OIQ](https://www.oiq.qc.ca/)).

Olivier La Haye holds a Bachelor's in Computer Science (Université Laval) and is not an OIQ member. Self-titling as "Engineer" or "Ingénieur" in user-facing text — even in the abstract sense of "engineering practice" — could create the appearance of a reserved title. This release replaces every such self-title with "Developer" / "Développeur" while preserving allowed exceptions (target job titles, third-party titles, official program names, awards, legal/research references).

## Compliance reason

- Quebec law reserves the title of "engineer" (and the discipline-prefixed forms) to OIQ members.
- The OIQ also actively pursues the use of derivative descriptors that imply membership.
- Even though, as of 2026, no reserved acts apply to software development specifically, the reserved title rule still applies to how a developer describes themselves in a professional product.
- The safe stance for a non-OIQ member shipping a product to recruiters is: never self-title as Engineer / Ingénieur.

## Title wording summary

- Self-title in EN: `Senior Design Engineer` → `Senior UI/UX Developer`.
- Self-title in FR: `Concepteur-développeur senior` → `Développeur UI/UX senior`.
- Practice noun in EN: `engineering practice` → `development practice`; `engineering voice` → `development voice`.
- Practice noun in FR: `pratique d'ingénierie` → `pratique de développement`; `voix d'ingénierie` → `voix du développement`.
- Skills group rename in EN: `AI-Native Engineering and Agent Orchestration` → `AI-Native Development and Agent Orchestration`.
- Skills group rename in FR: `Ingénierie native IA et orchestration d'agents` → `Développement IA natif et orchestration d'agents`.

## Allowed exceptions intentionally kept

The following uses of "Engineer" / "Ingénieur" / "Engineering" / "Ingénierie" remain in the resources because they refer to something other than Olivier's self-title:

- **Target job titles**: in the new EN summary the phrase `targeting senior Design Engineer, UI Engineer, and Frontend roles` describes target positions Olivier is applying for, not a self-title. In the new FR summary the same target titles are quoted as `Design Engineering, UI Engineering et Frontend`.
- **Awards**: `AMETEK Innovation Award 2022` is the official program name of an industry award given to a peel project team, not a self-title. Kept in both languages.
- **Held job titles at FARO Creaform**: `UI/UX Expert Software Developer` and `Software Developer` describe positions Olivier actually held, not the reserved title. Kept verbatim.
- **University/college program names**: `Bachelor's degree, Computer Science` (Université Laval) and `College Diploma, 3D Animation and Image Synthesis` (Cégep Limoilou). These are official program names, not self-titles. Kept.
- **Test fixture string**: `ResumeApp.Tests/Models/TimelineTimeFrameItemTests.cs` contains the string `"Senior Engineer"` as a test fixture for a fictional `CompanyX` role. It refers to a third-party role, not Olivier. Kept.
- **Term `Conçu` in FR**: the past participle of `concevoir` (to design / to conceive) appears 5 times in FR-CA accomplishments. It does not imply engineering practice and is not flagged by OIQ. Kept.

## Version source of truth

The repository previously had two non-aligned version sources:

- Marketing / release-tag version: `v3.1` (set in commit `4d9ada6`, April 2026).
- Assembly version constants: `1.0.0.0` (stale, never bumped).

This release aligns them. The single source of truth for the assembly version is now `Properties/AssemblyInfo.cs`. The `.csproj` sets `<GenerateAssemblyInfo>false</GenerateAssemblyInfo>`, so the `AssemblyVersion` and `AssemblyFileVersion` attributes in `AssemblyInfo.cs` win.

The application does not currently display its version anywhere in the UI (no About page, no version resource key). When a future change adds a visible version label, it should bind to the assembly version and show `v3.2` (April 2026) starting now.

## Validation

Validation commands (run on Windows 11, .NET 10 SDK):

```powershell
dotnet restore ResumeApp.sln
dotnet build ResumeApp.sln -c Release
dotnet test ResumeApp.sln -c Release
```

Banned-string searches (must return zero matches in user-facing values):

```powershell
# EN-CA self-title check
Select-String -Path Properties/Resources.resx -Pattern "Senior Design Engineer|engineering voice|primary engineering practice|AI-Native Engineering"

# FR-CA self-title check
Select-String -Path Properties/Resources.fr-CA.resx -Pattern "Concepteur-développeur senior|voix d.ingénierie|pratique d.ingénierie principale|Ingénierie native IA"
```

Parity check (EN-CA and FR-CA must have identical key sets):

```powershell
# Extract key names from each file and diff
Compare-Object `
  (Select-Xml -Path Properties/Resources.resx -XPath '//data/@name').Node.Value `
  (Select-Xml -Path Properties/Resources.fr-CA.resx -XPath '//data/@name').Node.Value
```
